Agent folders compile flows, subagents and vendored Agent Plugins (track T7). `agents/<id>/` of an agent is offered to it as a tool, as the TypeScript builder offers an agent used as a tool: named `<id>`, input `{ task }`, one level deep, with no `runtime.json`, `triggers/` or `files/` of its own. `flow.json` makes a folder a flow (`harness.kind: "workflow"`, v3's node tree): every `flow.json` under the flow root names stages from the root's one `agents/` by id, a stage with its own `flow.json` is a sub-flow, and the compiler embeds each agent where v3 wants it. `"tool": "<name>"` names `tools/<name>.json` beside the `flow.json`, and a loop's `verify` takes `{ agent }` or `{ tool }`. A flow's `AGENT.md` takes `inputSchema` and has no body; an unknown agent or tool is an error with its file, line, column and a did-you-mean, and an agent no flow names is a warning. `plugins/<name>/` folds a plugin's skills and `mcp.json` servers as `.plugin()` does, labelled, and notes what Nylorun does not run (hooks, commands). Diagnostics keep their file, line and column across nested folders (`agents/research/flow.json:3:12`). New codes: `flow_invalid`, `flow_body`, `flow_refused`, `flow_namespace`, `flow_cycle`, `agent_unknown`, `agent_unused`, `agent_name`, `tool_unknown`, `tool_unused`, `tool_twice`, `input_schema_refused`, `nested_refused`, `subagent_depth`, `credential_unsupported`, `plugin_invalid`, `plugin_unknown_key`, `plugin_duplicate` and `plugin_part_ignored`. `flow.json`, `agents/` and `plugins/` are no longer refused as `not_supported`.
